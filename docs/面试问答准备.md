**Task (任务)**
我需要将首屏加载时间控制在3秒以内，同时保证用户实际使用各个功能时不需要等待。

**Action (行动)**

**1. 双层懒加载架构**
```javascript
// 第一层：预加载（App.tsx）

  import('./ReactPlayground/components/AIAssistant').catch(() => {});
  import('./ReactPlayground/components/Preview').catch(() => {});
```

这样设计的好处是：首屏只加载核心框架，大型组件异步加载；预加载在后台进行，用户真正使用时组件已缓存。

- 配置pure_funcs移除指定函数调用
- 整体压缩率72%

**4. 组件层面优化**
- 使用React.memo避免不必要的重渲染
- useCallback缓存事件处理函数
- useMemo缓存编辑器配置
- 防抖处理用户输入（500ms）

**Result (结果)**

### Q3: 你提到的双层懒加载架构是什么？为什么这样设计？

**STAR回答：**

**Situation (背景)**
单纯使用React.lazy会导致用户首次点击功能时需要等待组件下载，体验不好。而传统的预加载又会阻塞首屏渲染。我需要找到一个平衡点。

**Task (任务)**
既要保证首屏快速渲染，又要确保用户使用功能时不需要等待。

**Action (行动)**

**架构设计：**
```
第一层（预加载层）- App.tsx
├── 在组件挂载后立即触发
├── 使用动态import异步加载
├── 不阻塞首屏渲染
└── 静默处理错误

第二层（按需加载层）- ReactPlayground/index.tsx  
├── 使用React.lazy声明
├── Suspense提供加载状态
├── 真正渲染时检查缓存
└── 已预加载则瞬间渲染
```

**核心代码：**
```javascript
// App.tsx - 预加载层
function App() {
  useEffect(() => {
    // 后台预加载，不影响首屏
    import('./ReactPlayground/components/CodeEditor').catch(() => {});
  }, []);
  return <ReactPlayground/>
}

// ReactPlayground/index.tsx - 按需加载层
const CodeEditor = lazy(() => import("./components/CodeEditor"))

<Suspense fallback={<LoadingSpinner message="正在加载代码编辑器..." />}>
  <CodeEditor />
</Suspense>
```

**工作流程：**
1. 0ms - 应用启动，只加载239KB核心代码
2. 600ms - 首屏渲染完成，用户看到界面
3. 800ms - React挂载完成，预加载开始
4. 1.2s - Monaco编辑器预加载完成
5. 2.5s - 所有组件预加载完成
6. 用户点击时 - 组件已在缓存，瞬间渲染

**Result (结果)**
- 首屏时间从12.5s降到3.2s（不含预加载）
- 用户切换功能时几乎无等待（已预加载）
- 即使预加载失败，Suspense仍提供优雅降级
- 网络较差时，用户先看到界面，功能逐步可用

### Q7: 文件状态如何实现URL持久化和分享？

**STAR回答：**

**Situation (背景)**
用户希望能够分享自己的代码，或者刷新页面后代码不丢失。需要将文件状态持久化到URL。

**Task (任务)**
实现文件状态与URL的双向同步，同时保证URL不会过长。

**Action (行动)**

**1. 压缩算法选择：**
```javascript
import { strToU8, strFromU8, compressSync, decompressSync } from 'fflate'

// 压缩
export const compress = (data: string): string => {
  const buffer = strToU8(data)
  const compressed = compressSync(buffer, { level: 9 })
  const binary = strFromU8(compressed, true)
  return btoa(binary) // Base64编码
}

// 解压
export const uncompress = (data: string): string => {
  const binary = atob(data)
  const buffer = strToU8(binary, true)
  const decompressed = decompressSync(buffer)
  return strFromU8(decompressed)
}
```

**2. 状态同步实现：**
```javascript
// 从URL恢复文件
const getFilesFromUrl = (): Files | undefined => {
  try {
    const hash = window.location.hash.slice(1);
    if (hash) {
      const decompressed = uncompress(hash);
      return JSON.parse(decompressed);
    }
  } catch (error) {
    console.warn('Failed to load files from URL:', error);
  }
  return undefined;
}

// 同步文件到URL
const syncFilesToUrl = (files: Files) => {
  try {
    const hash = compress(JSON.stringify(files));
    window.location.hash = encodeURIComponent(hash);
  } catch (error) {
    console.warn('Failed to sync files to URL:', error);
  }
}

// Store中自动同步
export const useFileStore = create<FileStore>((set, get) => ({
  files: getFilesFromUrl() || initFiles,
  
  setFiles: (files) => {
    set({ files });
    syncFilesToUrl(files); // 自动同步到URL
  }
}))
```

**3. 压缩效果：**
- 原始JSON: ~5KB
- fflate压缩: ~1.2KB
- Base64编码: ~1.6KB
- 压缩率: 68%

**Result (结果)**
- URL长度控制在合理范围内
- 用户刷新页面代码不丢失
- 支持代码分享功能
- 降级处理：URL解析失败自动使用默认模板

## 难点攻克类问题

### Q8: 项目中遇到的最大技术难点是什么？如何解决的？

**STAR回答：**

**Situation (背景)**
AI助手功能需要实现类似ChatGPT的流式打字效果，但如果每收到一个字符就更新UI，会导致：
1. React频繁重新渲染，CPU占用高
2. 滚动条抖动，用户体验差
3. 移动端性能问题明显

**Task (任务)**
实现流式响应的同时，保证UI流畅，CPU占用合理。

**Action (行动)**

**1. 缓冲机制设计：**
```javascript
export class OptimizedAIService {
  private buffer: string[] = [];
  private lastFlushTime = 0;
  private readonly flushInterval = 200; // 200ms批量刷新

  async chatStreamOptimized(
    message: string,
    onChunk?: (chunk: string) => void
  ): Promise<string> {
    // 缓冲处理函数
    const flushBuffer = () => {
      if (this.buffer.length > 0) {
        const content = this.buffer.join(''); // 合并所有内容
        this.buffer = [];
        this.lastFlushTime = Date.now();
        onChunk?.(content); // 一次性更新UI
      }
    };

    this.currentEventSource.onmessage = (event: MessageEvent) => {
      const data = JSON.parse(event.data);
      if (data.content) {
        this.buffer.push(data.content); // 添加到缓冲区
        
        // 检查是否需要刷新
        const now = Date.now();
        if (now - this.lastFlushTime >= this.flushInterval) {
          flushBuffer();
        }
      }
    };

    // 监听完成事件
    this.currentEventSource.addEventListener('done', () => {
      flushBuffer(); // 最后一次刷新
      resolve(fullResponse);
    });
  }
}
```

**2. 性能对比：**

| 方案 | UI更新频率 | CPU占用 | 用户体验 |
|------|-----------|---------|----------|
| 逐字更新 | ~100次/秒 | 高 | 卡顿 |
| 缓冲200ms | ~5次/秒 | 低 | 流畅 |

**3. Server-Sent Events选择：**
- 相比WebSocket更轻量
- 自动重连机制
- 原生浏览器支持
- 单向通信满足需求

**4. 错误处理：**
```javascript
// 请求超时
setTimeout(() => {
  if (this.currentEventSource) {
    this.currentEventSource.close();
    reject(new Error('请求超时'));
  }
}, 30000); // 30秒超时

// 取消请求
cancelCurrentStream(): void {
  if (this.currentEventSource) {
    this.currentEventSource.close();
    this.currentEventSource = null;
  }
}
```

**Result (结果)**
- UI更新频率从100次/秒降到5次/秒
- CPU占用降低80%
- 用户体验流畅，无卡顿
- 支持请求取消，避免资源浪费
- 移动端也能流畅运行

**Task (任务)**

**Action (行动)**


**2. React.memo优化：**
```javascript
// 编辑器组件使用自定义比较

  );
})

// 预览组件使用默认比较
```

```javascript
  // 编辑器配置
```

**Task (任务)**

**Action (行动)**

**1. 选择Server-Sent Events：**
```javascript
// 后端实现（Node.js + Express）
app.get('/api/chat-stream', async (req, res) => {
  res.setHeader('Content-Type', 'text/event-stream');
  res.setHeader('Cache-Control', 'no-cache');
  res.setHeader('Connection', 'keep-alive');

  const stream = await openai.chat.completions.create({
    model: 'gpt-4',
    messages: [...],
    stream: true
  });

  for await (const chunk of stream) {
    const content = chunk.choices[0]?.delta?.content || '';
    if (content) {
      res.write(`data: ${JSON.stringify({ content })}\n\n`);
    }
  }

  res.write(`event: done\ndata: {}\n\n`);
  res.end();
});
```

**2. 前端消费流式数据：**
```javascript
this.currentEventSource = new EventSource(`http://localhost:3001/api/chat-stream?${params}`);

this.currentEventSource.onmessage = (event: MessageEvent) => {
  const data = JSON.parse(event.data);
  if (data.content) {
    this.buffer.push(data.content); // 添加到缓冲区
    
    // 200ms批量更新
    if (Date.now() - this.lastFlushTime >= 200) {
      flushBuffer();
    }
  }
};
```
